# 周期200 nmのPMMA+Au：高さ別のNV次数依存性

```bash
python -u run_au_pmma_nv_height_orders.py \
  --device cuda:0 \
  --heights-nm 400,300,200 \
  --wavelengths 700 \
  --start-order 4 --step 2 --max-order 36 \
  --slices 210 --grid 512 \
  --tolerance 0.005 \
  --output-root studies/au_pmma_nv_height_orders/results/P200_H400-200_Nz210_Q512_M4-36_700nm
```

高さ3条件×M=4,6,...,36の17条件×波長700 nm＝51ケース。周期200 nm、PMMA先端半径5 nm・底面半径65 nm、Au側面・上部・谷部30 nm、プロファイル層数210（上部キャップを含め211層）、垂直入射x偏光、三角格子。全高は430/330/230 nmになる。NV/D6・complex128・Redheffer・Lanczosなし。光学定数は従来のAu/PMMAデータと同じ。

`run_au_nv_height_diagnostics.py`を介して既存のメモリ節約NVソルバーと層別診断を変更せず使用する。実行ファイルは両方と既存の依存ファイルをプロジェクト直下に置く。前の高さ200 nm・周期100 nmの専用スクリプトは使用しない。

各ケースは別プロセス。OOM・計算例外・非物理値でも他のケースを続ける。完了ケースは同じコマンドで再利用し、失敗ケースの再試行は`--retry-failures`。元の別バッチからのコピー再利用はせず、同じ出力先の一致するケースだけを再利用する。`--dry-run`は形状・材料・条件数を確認し保存しない。`--plot-only`は計算せず同じ設定の保存結果から集計・描画する。

各高さについて`order_RTA_H400_...png/svg`等に次数に対するR/T/Aを横3列で描画する。負の積分層吸収のあるケースには赤い×を付け、失敗条件で線を切る。`order_passivity_H400_...png/svg`等で負の層数・最小層吸収・負の固有値成分への励起量を描画する。

`height_summary.csv/json`には各ケースの結果と層別パワー等の保存先を記録する。`order_tail_checks.json`と`order_tail_changes.csv`で最後の3次数（デフォルト32,34,36）の隣接変化を確認する。`--tolerance 0.005`は各R/T/Aの絶対変化0.5パーセントポイント。R/T/Aの変動、実際の負の層吸収、数値整合性は別々に表示する。厳しい負の固有値成分への寄与の判定をR/T/Aの誤差と見なさない。

この掃引は固定Nz/Qでの次数依存性の確認であり、層数・グリッドの収束を保証しない。終了コード0も全ケースの実行完了を意味し、物理的妥当性や収束済みを意味しない。

従来のH100・同じNz210/Q512・PMMA+Au高さ500 nmの700 nm掃引（17次数）のソルバー実行時間合計は約3.36時間。3高さでは約10.1時間、起動・診断・入出力・機器差を含め10〜14時間程度を目安とする。待ち時間は含めず、同等H100での概算である。M36のメモリは約86 GiBに達したため、従来成功した約93 GiB級のGPUが必要。高さを下げても層数と次数を固定するとメモリはほぼ減らない。
