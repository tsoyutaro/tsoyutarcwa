# M=48・700 nm の誤った K_y 判定を修正

垂直入射の設定は正しく、メモリ不足でもありません。
一次元アダプタが継承していた一般の斜交格子の式で、90° の余弦に浮動小数点の残りが生じていました。

垂直入射・y 方向の次数 0 では、一般式は次のようになります。

`K_y(m) = -cos(zeta)/sin(zeta) * m * wavelength/period`

90° では数学的に 0 ですが、`math.cos(pi/2)` は約 6.123234e-17 です。
M=48、700 nm、周期200 nm では最大値が **1.028703311e-14** になり、`add_ridge` のしきい値 1e-14 を超えていました。
M=48・650 nm までは超えないため、ログの停止位置と一致します。

## 修正

`solver.py` の `Grating1D._kvectors()` で、角度が厳密に90°であることを確認し、余弦を0・正弦を1としてから波数、電磁場のポート行列、境界の S 行列を構成します。
しきい値を緩める変更ではありません。実際に K_y が非零の入射は引き続き拒否します。
RCWA 共通本体の変更はありません。

## 同じコマンドで再開

このフォルダの `solver.py`、`run_analytic.py`、新しい `resume_checkpoint.py` を Linux の同名フォルダへ反映します。

```bash
python3 studies/gold_grating_1d/run_analytic.py --device cuda
```

計算ソースのハッシュが変わるため、再開時に次の確認を行います。

1. 保存されたソースの差が今回の既知の `solver.py` の修正だけで、構造・材料・他のソースが一致することを確認。
2. 保存済みの最大3次数について、その次数の最大層数・最大波長のケースを再計算。
3. TE/TM の R・P_sub・A_relief の差が全て **1e-8以下（0–1の値）** であることを確認。
4. 元の checkpoint を `checkpoint_before_orthogonal_fix_<signature>.json` にそのままバックアップしてから再開。

今回のログなら、M=32・700 nm、M=40・700 nm、M=48・650 nm（全てNz=300）を照合します。
通過すれば、完了済みの20ケースを再利用し、M=48・700 nmから残りの計算を続けます。
初期二軸比較で残っているのは29ケースで、候補の再確認は追加されます。
元の計算値・時間は保存し、各再利用ケースと report に由来・照合記録を残します。

この照合は今回の丸め誤差修正との整合性確認です。次数・層数の収束判定は通常どおり別に行います。
他の計算ソースも変わっていた場合、または照合が不合格だった場合は、古い checkpoint を変更せずに停止します。
新しく計算する場合の出力先指定例：

```bash
python3 studies/gold_grating_1d/run_analytic.py --device cuda \
  --output-dir studies/gold_grating_1d/results/analytic_search_exact_orthogonal
```

旧 checkpoint からの最初の再開は、照合の計算が必要なので `--report-only` または `--prepare-only` を付けずに実行します。
再開後は、それらのオプションを従来どおり使えます。

## 確認

CPUで元のM=48・700 nmのエラーを再現し、修正後の K_y が厳密に0であることを確認しました。
回帰テストと保存結果の照合・バックアップ・再開テストの計16件、既存の小さな物理検証5件が通過しました。
M=48と56、Nz=300、700 nm の全層計算がCPUで完了し、R・P_sub・A_relief が範囲内であることも確認しました。
M=40、Nz=300、700 nm の新旧計算の R・P_sub・A_relief の最大絶対差は0でした。
これらは実行・整合性の検証で、探索範囲全体の収束を示すものではありません。
CUDA環境はローカルに無いため、GPUでの照合は再開時に実施します。
